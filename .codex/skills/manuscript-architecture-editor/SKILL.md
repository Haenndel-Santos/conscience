# Manuscript Architecture Editor

## Quando usar

Use ao transformar notas, ensaios ou capítulos em uma estrutura de livro. Acione quando o trabalho envolver sumário, ordem de capítulos, transições, equilíbrio entre seções, redundância, prefácio, conclusão, implicações, apêndices ou preparação de preprint.

## Quando não usar

Não use para resolver problemas conceituais profundos sem edição estrutural. Para defesa do núcleo, use `theory-core-guardian`; para citações, use `citation-and-reference-guardian`; para casos-limite, use `boundary-cases-lab`.

## Objetivo

Fazer o manuscrito funcionar como livro de aproximadamente 150 páginas: progressivo, legível, teoricamente denso, com capítulos conectados e uma voz autoral estável. A arquitetura deve ajudar o leitor a acompanhar a passagem de corpo e integração para agência, socialidade, formalismo, casos-limite e IA.

## Restrições

- Manter tom acadêmico-ensaístico, não manual técnico nem colagem de fichamentos.
- Evitar capítulos que apenas acumulem temas sem função argumentativa.
- Cada capítulo deve ter uma tese, um problema, um desenvolvimento e uma transição.
- Não usar linguagem de bastidor como "esta versão", "o usuário pediu" ou "na resposta anterior".
- Não criar seções decorativas; cada seção deve mover o argumento.
- Preservar a intuição originária da teoria ao reorganizar.
- Evitar excesso de bullet points no manuscrito final; usar prosa conectiva.

## Checklist operacional

- Mapear a função de cada capítulo em uma frase.
- Verificar se a sequência do livro cria necessidade argumentativa, não apenas enumeração temática.
- Localizar lacunas de transição entre corpo, regime, determinismo, socialidade, formalismo e IA.
- Marcar repetições úteis e repetições improdutivas.
- Sugerir cortes, fusões ou deslocamentos sem descaracterizar a voz.
- Equilibrar abertura conceitual, exemplos concretos, densidade teórica e síntese.
- Garantir que a conclusão retome a teoria como regime integrado, não como resumo burocrático.

## Exemplos de prompts

- "Proponha uma arquitetura de livro de 150 páginas a partir deste sumário."
- "Revise as transições entre estes capítulos."
- "Diga onde este capítulo está longo, repetitivo ou deslocado."
- "Reorganize estas seções para melhorar progressão argumentativa."

## Saída esperada

Entregue recomendações editoriais com hierarquia clara: diagnóstico estrutural, proposta de ordem, função de capítulos, pontos de transição e eventuais trechos-modelo. Quando sugerir nova estrutura, explique a razão de cada movimento.

## Erros comuns a evitar

- Transformar o livro em revisão bibliográfica sem tese própria.
- Inserir prefácio ou conclusão genéricos.
- Resolver problemas de arquitetura apenas expandindo texto.
- Criar capítulos independentes que não conversam entre si.
- Sacrificar legibilidade por densidade conceitual.
